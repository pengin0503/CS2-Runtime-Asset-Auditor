# ランチャー非表示の修正とパネル開閉キーの検証状況 — 2026-09-29

ゲーム画面左上のランチャーアイコンが表示されずパネルを開けない問題の修正と、パネル開閉キーの追加について、実施した検証と未実施の項目を記録する。自動テストの成功を実機での PASS とは扱わない。

## 原因

ユーザー環境のログ（`FileSystem.txt`）では、`Mods\CS2RuntimeAssetAuditor` に DLL・PDB・`0Harmony.dll` しかなく、UI バンドル（`CS2RuntimeAssetAuditor.mjs`・`.css`・アイコン画像）がなかった。ゲームは `.mjs` のヘッダー（`Cities: Skylines II UI Module` / `Id:`）を持つファイルだけを UI モジュールとして登録するため（`Colossal.IO.AssetDatabase.UIModuleAsset`）、DLL は読み込まれてもランチャーは表示されない。

UI ビルドのターゲットは `Condition="Exists('$(SolutionDir)UI\package.json')"` だった。README の手順どおりプロジェクト単体をビルドすると `$(SolutionDir)` は `*Undefined*` になり、条件が偽になって UI ビルドが警告なしで省略されていた。この挙動は .NET 8 SDK の MSBuild で再現した。

## 修正

- UI プロジェクトを Mod プロジェクトからの相対パスで解決し、UI バンドルを Mod の出力フォルダーに作成してから、公式 Toolchain の `DeployWIP` がローカル Mod フォルダーへコピーする。`DeployWIP` は配置先を削除してからコピーするため、UI を配置先へ直接書くと削除され得る順序依存もなくなる。
- UI の依存関係が未インストールの場合、または `.mjs`・`.css`・アイコンのいずれかが出力にない場合はビルドをエラーにする。
- オプションに「キー割り当て」→「診断パネルの開閉」を追加した。既定キーはない（`SettingsUIKeyboardBinding` に既定キーを渡さず `BindingKeyboard.None`）。キーバインドは設定の読み込み前に登録し、UI システムが毎フレーム（UI 更新の間引きより前に）入力を確認する。
